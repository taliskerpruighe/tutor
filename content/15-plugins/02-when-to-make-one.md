# When to make one

*v0.2.0*

Most of what you build has no reason to leave the project it was
built for. A plugin is worth the extra step in four situations, and
they are worth knowing apart, because they call for the same move for
different reasons.

## You need it, but rarely

A suite that earns its place once or twice a year still costs
something every session it sits in, whether you use it that day or
not — *Context rot* is why. A redaction suite for subject access
requests, built for the handful of matters a year that need one,
should not sit loaded into every ordinary drafting session between
them. Keep it as a plugin and install it only into the matter that
needs it that week.

## Two projects need the same thing, and nothing above them should

Two client matters can want the identical suite — a citation checker,
say — while sharing nothing else, and sitting nowhere near each other
in your folder structure. Putting the suite somewhere above both of
them in the tree would hand it to every other matter underneath as
well. A plugin gets it into exactly those two projects and no others,
which a shared folder higher up cannot do without also widening who
else sees it.

## The project ends, the suite should not

A suite built for one piece of litigation — a chronology builder tuned
to that bundle's document types — can outlive the case it was built
for. If the project folder gets archived or deleted when the matter
closes, anything written only into its `.claude` closes with it. A
plugin survives that, ready for the next matter shaped the same way.

## You want to hand it to someone

A suite is also worth sharing, and a plugin is the form that travels —
to an assistant, to another fee-earner, to your own machine at home.
Handing over a project folder hands over the matter with it. Handing
over a plugin hands over only the tooling.

## The best case

All four reasons converge on one shape: a single piece of plumbing,
improved continuously, used from more than one place. A voice agent is
the clean example — one skill teaching it to write in your register,
one skill to send the result as email, built once and then fed new
examples of your own writing every week. It runs the same way from a
personal project and a work one, gets better in both at once, and
never has to be rebuilt in either.

That is the case for building a plugin. Most suites still belong where
they were built. The next article is what one is actually made of.
