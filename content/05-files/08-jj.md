# jj

*v0.2.0*

**jj** — Jujutsu — does the same job as git, on the same history, and
mostly reads it out of the same git storage underneath. What changed is
the handling: two of git's oldest sharp edges are simply not there.

## The staging area, removed

Git makes you decide, separately from writing the file, which changes
go into the next commit — a step called staging, done with its own
command, that sits between editing and committing. Skip it and the
commit is empty; get it half right and the commit holds some of your
changes and not others, silently.

jj has no staging area. Whatever is in the file is what the next commit
holds, always, because your working copy is not something *pending* a
commit — it already is one, updated automatically every time jj looks
at it.

## Nothing is ever mid-air

Git also has a state called a detached HEAD — working on a commit that
is not the tip of any branch, easy to end up in by accident, and easy
to lose work out of if you move away from it carelessly. jj does not
have an equivalent trap. Every piece of work is always a real commit
sitting in the history, from the moment it exists, so there is nothing
to lose by looking away from it.

That single design choice removes most of the moments where git asks
you to understand its own internals before it will let you continue.

## Why anyone switched

Not because git was replaced. jj commonly runs **colocated** with a git
repository — the same folder, the same underlying history, readable by
either tool — so a jj user can hand the exact same repository to a
colleague who has never heard of jj and nothing breaks. The Boss adopted
it for that reason specifically: fewer steps, the same result, no
retraining anyone else it is shared with.

## What it costs

Git is the tool nearly everyone else already has installed, already
half-knows, and already assumes when they write instructions or build
software that touches a repository. jj is a second thing to have
learned, useful mainly once the first one has stopped feeling foreign —
not a replacement to reach for on day one.

That is the honest trade: a smoother tool, on top of a history that
every other tool in this world still expects to be git's.

The history itself, either way, is just a folder on your machine. The
next article is what turns it into something more than one — a copy of
it that other people can reach.
