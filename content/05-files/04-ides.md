# IDEs

*v0.2.0*

An **integrated development environment** — an **IDE** — is a single
program built to hold every step of writing software at once: the
project's files down one side, the code you are editing in the
middle, a built-in terminal along the bottom, and a button that runs
what you just wrote without leaving the window.

Two names cover almost every IDE you will hear mentioned.

## The two you will hear named

**VS Code** — Visual Studio Code — is Microsoft's, free, and the most
widely used IDE there is. Its plugin system is enormous, and it is
one of the editors Claude Code's own integrations reach into, putting
the agent in a panel beside your files rather than in a terminal of
its own.

**The JetBrains family** — IntelliJ, PyCharm, WebStorm and half a
dozen others, one per major language — is the mostly commercial
alternative, built by a single company, each member tuned tightly to
one kind of project. A developer working chiefly in one language
often prefers the JetBrains tool built for it over VS Code's
generalism.

## Not built for you

An IDE earns its keep for someone whose whole day is writing and
running code: jumping between forty files in one project, stepping
through a program line by line to find where it breaks, renaming a
function used in sixty places without missing one. Every feature on
that toolbar is aimed at that day.

That is not your day. You have one file open, perhaps two, and the
work you actually want done — read this bundle, draft that letter,
find every reference to a clause — is not the job an IDE was built
to speed up. Its terminal panel would still be the thing doing the
work; the rest of the window is furniture built for someone else's
job.

None of that makes an IDE bad software. It makes it software with an
opinion about what your day looks like, aimed at a reader who spends
hers moving between forty files rather than one bundle.

## What that sets up

Claude Code can run inside an IDE exactly like this, in a panel
beside your files. That earns its place for someone jumping
constantly between an answer and the file it belongs to — a
developer's day, not yours. The rest of this course happens in a
terminal of its own instead, and the next article is about what runs
in that terminal when the file you are looking at needs a nudge by
hand.

Press `n`.
